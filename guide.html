圈问白板使用指南

给项目建白板、沿卡片追问，或用技能把 Codex／ZCode 的工作成果写回原板。

开始使用 选择技能 文件工作流

开始使用

  1. 在项目首页打开或添加本机项目。进入后从结构总览读取模块关系和项目资料。
  2. 点卡片看右侧说明、证据或「问这张卡」。用「＋」展开已有下级。要新增下级，右键点「AI 向下延伸」，生成预览后勾选保存。
  3. 在右上角「连接设置」选择 Codex、ZCode 或 API 直连。等到页面显示已保存到本机服务，再把白板链接交给别人或其他会话。
打开示例卡片 · 附件、连接设置和事件流

选择技能

以下是白板仓库提供的四个技能。在外部 Codex／ZCode 会话中，可以直接报技能名，并附上白板链接、目标卡号和你希望完成的事。

本机初始化 whiteboard-local-setup
启动白板、扫描指定工程目录、登记项目及子项目。适合第一次接入本机项目。
查看技能原文
项目源码分析 whiteboard-project-analysis
从使用场景追到源码入口、方法、参数、边界和验收。适合整理可逐级展开的项目手册。
查看技能原文 · 项目模块图出图范式
把工作成果落板 whiteboard-content-handoff
找到正确的白板和父卡，判断应更新现有卡还是增加下级，再核对实际保存结果。
查看技能原文
从外部直接读写 whiteboard-service
通过本机服务查板、导出分支、预览并提交修改。适合已有内容，只需更新或追加到现有分支。
查看技能原文

可以这样交给 AI：「用 whiteboard-service 打开这张白板，把本轮验收结果补到 E27 的对应子卡。先核对已有内容，提交后告诉我卡号和保存版本。」

文件工作流

在白板仓库根目录执行。示例使用代码仓库详解手册的 E27，实际操作时替换成你要改的板号和卡号。

  1. 导出目标分支、祖先、项目规则和此次读取的版本。 
    python scripts/whiteboard_service.py checkout --board repo-manual --node E27 --out board-work
  2. 阅读 context.json，只编辑 proposal.json。用 updates 更新卡片，用 children 增加下级。
  3. 先预览范围与父子关系，再提交。服务保存后，用 receipt.json 核对卡号和版本。 
    python scripts/whiteboard_service.py submit --workspace board-work
python scripts/whiteboard_service.py submit --workspace board-work --commit

工作文件用来准备修改，最新白板由本机服务保存。版本有变化时，重新导出分支并合并差异。
