# 项目模块图出图范式

这份范式供白板服务、Codex 和 ZCode 共用。先写清读者想弄明白的问题，再用分区、简短卡片和有依据的连线，把实际工作的关系画出来。

- **入口**用项目标题和一两句导读回答项目做什么、怎样使用或验收。图名说明这张图的阅读目的，例如「从输入到复核」。
- **分区**按项目实际任务组织，例如输入与基准、主要工作、并行对照、输出与验收。用大小和列位置突出主要工作，相关主题放在同区或相邻列。简单项目可以只用一个分区。
- **节点**引用真实卡号，展示面向使用者的短标题和可观察的结果。项目级总览让根卡与各直属能力可见，具体实现、参数和长说明留在现有卡片里。结果和待验收项用已有证据说明。
- **连线**只画有依据的输入输出、执行顺序、分支或回写。标签写出传递的内容或关系，如「低置信送复核」。用主路径 `main`、旁路 `side`、回写 `back` 区分含义。每条线引用一张能说明该关系的证据卡。仅共享父卡的主题可以并列，关系未知时留空。
- **下钻**以原卡为根打开该模块，沿用同样的分区和连线语法。已有模块图、实验对比和证据继续用原卡承载。

## 交付格式

「初始化工程介绍」在卡片和层级之外生成 `projectStructure`。根卡和每张直属功能卡在总览中各出现一次。更深层的卡可以给连线提供依据。列 `lane` 从 0 开始，主路径通常从左到右，独立主题也可在同列上下排列。

当下级模块有明确的执行顺序、分支或验收关系时，在 `moduleDiagrams` 中按相同格式记录。每张图以该模块为根，画出它和直属卡，连线依据从该模块的子树取。点「＋」会在父图下方打开独立的子模块白板，界面自动从来源卡画出导航连线。用分组框表达同一张图里的归属，用已登记的业务关系表达图内的动作与方向。

外部 Codex 或 ZCode 处理现有白板时，先读取目标模块的真实卡号和证据。以对应卡为 `rootId` 生成同样的 JSON，在该模块的「图设置 → 编辑模块图」中校验并保存。以下示例使用虚构卡号和内容，E07 代表记录转交条件的依据卡。实际交付时换成对应白板的真实卡号与关系。

```json
{
  "version": 1,
  "rootId": "E04",
  "title": "从提交到复核",
  "zones": [
    {
      "id": "intake", "title": "提交", "role": "entry", "size": "medium", "lane": 0,
      "nodes": [
        {"id": "goal", "cardId": "E04", "label": "核对一次申请", "note": "接收申请并提供可追溯的结果"},
        {"id": "form", "cardId": "E05", "label": "接收申请", "note": "收齐必填信息后记录申请"}
      ]
    },
    {
      "id": "review", "title": "人工复核", "role": "feedback", "size": "large", "lane": 1,
      "nodes": [
        {"id": "queue", "cardId": "E06", "label": "核对缺失信息", "note": "复核员确认或退回待补材料"}
      ]
    }
  ],
  "links": [
    {"from": "form", "to": "queue", "label": "缺少附件时转交", "kind": "side", "evidence": "E07"}
  ]
}
```

`from` 和 `to` 引用图内节点的 `id`，`cardId` 和 `evidence` 引用白板卡号。分区角色可选 `entry`、`capability`、`external`、`store`、`feedback`，大小可选 `small`、`medium`、`large`。
