# 圈问白板功能说明

圈问白板用来把一个实际项目讲清楚，并把理解转成可以讨论、修改和验收的工作。一个项目可以先从总览看边界，再展开到功能、文件、调用过程和测试。讨论留在相关卡片旁边，经过确认的内容可以归入主干。此文按使用目的说明功能入口、操作结果和目前的边界，供使用白板和改动功能时对照。

本文以标准版为主。本机 8797 讲义版有自己的阅读入口，详见第 9 节。第 1 节的首页、添加项目与关闭项目适用于标准版。

## 使用主线

1. **首页选项目。** 已登记的工程点「打开项目」。首次使用可点「添加项目」，填名称和本机已有的目录。单纯想写内容时，可从首页新建一张独立白板。
2. **在画布上写或读。** 空画布点「写第一张卡片」，把问题、需求或约束保存为主干。想先熟悉仓库时，可以用 Codex 或 ZCode 初始化工程介绍。接着选卡提问、拆细或手动连线。
3. **在项目内查看结果。** 用「项目图」看结构，用「AI 动作」回看已有动作。要继续写时，切回「项目画布」。
4. **关闭并回来继续。** 点「关闭项目」回首页。项目目录与已保存的画布会在再次打开时恢复。未完成的任务需先结束或停止，未保存的草稿在离开前会提示。

## 1. 白板和项目

| 功能与入口 | 要解决的问题 | 操作结果与边界 |
| --- | --- | --- |
| **首页 → 打开项目 / 添加项目** | 在一个入口选定接下来要工作的工程。 | 默认打开该项目的画布。添加时登记本机已有目录，同一目录再次添加会打开原项目。 |
| **已在其他本机服务运行的白板** | 从首页继续使用原画布和它的资料。 | 项目有 `boardUrl` 时，「打开项目」直接访问其本机白板链接。当前卡片、讲义图片和历史记录由原服务与浏览器提供。 |
| **关闭项目 / 关闭白板** | 结束当前工作，回首页选择下一项。 | 已保存的内容和目录可随时再次打开。正在执行的任务结束或停止后可关闭，未保存的编辑会在离开前提示。 |
| **首页 → 独立白板 / 示例与手册** | 打开随手写的板、案例或读码手册。 | 每张板分别保存卡片、关系、项目规则与项目目录。打开独立板后也可用顶部「切换白板」。 |
| **管理 → 新建白板** | 从空白开始读一个仓库，或为一项工作开出独立空间。 | 填写白板名称，可同时绑定项目目录。新板单独保存，目录可稍后补填。 |
| **管理 → 项目目录** | 让 Codex 或 ZCode 查看这张板所讨论的实际项目源码。 | 填写本机目录，服务验证后保存到当前板。留空时使用白板项目目录。切换目录会清除本轮改码授权，已写入板上的说明应按新目录重新核对。 |
| **管理 → 删除当前白板** | 移除已弃用的独立白板或示例板。 | 确认后清除本浏览器中的该板数据并回到首页。白板级删除有独立的确认流程，画布上的「撤销删除」用于恢复卡片。 |
| **空画布 → 写第一张卡片** | 从一个问题、需求或约束开始组织项目。 | 卡片保存在当前板的主干。写完可直接将其作为选区提问、拆分或继续连线。 |
| **打开已有介绍的项目** | 直接从项目总览读到实现、源码和验收。 | 本机项目快照带有介绍时，会填充尚无内容的画布。细节可逐级展开，也能继续提问和编辑。已写过的卡片、讨论和项目规则保留。 |
| **空白自建板 → 初始化工程介绍** | 为陌生仓库建立可逐级读下去的导览。 | Codex 或 ZCode 按项目目录查看项目说明、实际入口、关键模块和测试，生成「总览 → 章节 → 细节」，并核对卡片的源码引用。服务还可在首轮加入最多两张源码片段卡。生成后可收起细节，可用「撤销整理」恢复初始化前的板面。 |
| **更多工具 → 项目设计模板** | 先建立可直接讨论的项目定义、系统设计和交付结构。 | 明确确认后，用模板替换当前白板。可通过「撤销上次白板替换」恢复备份。模板内容用于起步，适用范围与事实仍需结合自己的项目确认。 |
| **预置手册与样板** | 学习怎样从项目全貌读到函数，也能参考已组织好的示例。 | 「项目定义与交付」展示目标、边界和交付结构。「代码仓库详解手册」按浏览器实现、模型执行、验证等路径展开。「源码架构手册（Codex）」另有独立读码样板。自建板可采用同样的组织方法。 |

入口与数据来源见 [index.html](../index.html)、[memory.js](../memory.js)、[repo_index.py](../repo_index.py) 和 [server.py](../server.py)。白板生命周期、目录绑定和工程初始化对应浏览器验收 U50、U51、U55、U56。

## 2. 浏览、圈选与移动

| 功能与入口 | 要解决的问题 | 操作结果与边界 |
| --- | --- | --- |
| **空白处拖动、方向键、滚轮** | 在大画布上快速换位置，减少工具切换。 | 任一模式下拖空白处可平移。点进画布后用方向键移动视野，Shift 加快。鼠标滚轮或触控板双指滑动可平移，Shift + 滚轮横移。按住空格或鼠标中键拖动，可从卡片上临时平移。 |
| **加减号、Ctrl / ⌘ + 滚轮、适应整个白板** | 在浏览全貌和读一张卡之间切换。 | 加减号改变缩放比例，组合滚轮以指针为缩放中心，「适应整个白板」重新把可见内容放进视野。缩放和平移改变的是视野。 |
| **圈选模式 → 点卡、圈局部、圈多张** | 明确这一轮讨论哪张卡或哪一段。 | 点卡选择整张，Shift 点选增减卡片。在卡上拖动画圈可命中文本、公式片段或图形。需要从空白处开始圈多个对象时，按住 Shift 再拖动。选区可在侧栏确认，也可直接点附近的「问 AI」。 |
| **移动模式、圈选后的拖动把手** | 把相关卡一起移开，让局部更容易阅读。 | 移动模式下可拖单卡，或用 Shift 多选后拖其中一张来移动整组。圈选命中整卡也可直接拖把手。手动拖动会保存坐标，拖动中按 Esc 可取消。 |
| **搜卡 → 定位 → 回到总览** | 在大板里找到折叠或离开视野的内容。 | 按标题、编号、正文或已关联的源码符号查找。选择结果后临时展开到目标的路径、定位并选中卡片。可以直接提问。点「回到总览」会收回为搜索临时展开的部分。 |
| **右键菜单** | 在鼠标当前位置操作，减少来回点工具栏。 | 空白处可以在此新建卡片或独立提问。点卡片可编辑、固定、删除，连线模式下可右键删除连线。菜单也能切换圈选、移动、图钉、连线，具体选项随目标和任务状态变化。 |

选区交互见 [geometry.js](../geometry.js)，视野、拖动和搜卡见 [app.js](../app.js)。回归用例包括 U37、U44、U45、U53、U54 和 U61。

## 3. 卡片、关系和排布

| 功能与入口 | 要解决的问题 | 操作结果与边界 |
| --- | --- | --- |
| **新建卡片、编辑卡片** | 手工写下设计问题、约束或补充说明，再交给 AI 细化。 | 工具栏可新建，右键「在此新建卡片」使用鼠标所在的画布坐标。卡片可编辑标题、正文和用途。已有任务可编辑依赖和验收条件。 |
| **图钉模式、右键固定** | 告诉白板哪些内容是重点。 | 点卡添加或取消红色图钉。标准版整理时保护重点卡，快速重排保留已固定的坐标，仍可手动拖卡。8797 讲义版图钉的行为见第 9 节。 |
| **展开正文 / 收起正文** | 只看标题或简述时减少信息量，需要时读原文。 | 控制本卡的文字显示。回答总览保留原回答时，可通过「查看原回答」读全文。 |
| **展开下级 / 收起下级** | 从项目全貌往下读，读完可把细节收起来。 | 根据父子关系控制下级显示，按钮显示下级数。关系和折叠状态随板保存。收起分支后移开父卡，再展开时会按父卡当前位置安排下级。 |
| **连线、删除连线** | 手工修正归属和箭头方向。 | 在连线模式依次点父卡、子卡，或按住 Shift 从父卡向子卡拖动。箭头指向子卡，重新连线可替换子卡的主要父卡。操作在本地完成，白板检查自连和循环。删除一条线只解除关系。 |
| **快速重排整个白板** | 在卡片增加或位置凌乱后整理可见布局。 | 空选区时，每点一次在紧凑树形、横向展开、双侧展开之间切换。本地计算位置，能在等模型时使用，可撤销重排。 |
| **快速重排选中分支** | 只整理眼前正在看的模块，保留相邻分支的位置。 | 选中模块后按钮变为分支重排。父卡作为锚点，可同时选多个分支。各分支记住各自的排布样式，收起的内容在展开时再参与排布。 |
| **删除选中、撤销删除、重试关系整理** | 删除过期卡片，并处理仍有用的下级。 | 删除叶节点或选齐完整子树时，本地直接保存。若还有受影响的卡片，先移除已选内容，再按状态整理剩余关系，失败时可重试。回答进行中可删与本轮无关的卡，正在处理的卡及受保护的下级要等本轮结束或停止。撤销可恢复本轮删除前的关系和位置。 |

白板以关系数据计算分支归属和下级计数。手动拖动改变坐标，连线、归位和受校验的整理才改变归属。主干的顺序线也可表示阅读顺序，删除时按真实归属处理。关系与排布见 [app.js](../app.js)、[organization.js](../organization.js) 和 [memory.js](../memory.js)。相关用例包括 U30 至 U35、U40 至 U42、U49 和 U58。

## 4. 提问、整理和草稿归位

| 功能与入口 | 要解决的问题 | 操作结果与边界 |
| --- | --- | --- |
| **问 AI → 发送** | 在卡片旁核实一句话、公式、文件或某段实现。 | 发送问题与当前选区，模型根据意图判断如何处理。普通结果以批注显示在来源附近，批注又可以作为下一轮选区。提问时可以明确要求重答当前批注、向下延伸或添加主干模块。改码授权另见第 5 节。 |
| **问整个白板** | 跨章节了解全貌，或查找尚未定位的问题。 | 白板根据问题检索相关卡片，结合可用的总览、项目规则和关系提交。已保存的折叠卡可被检索，提交上下文受长度预算限制。 |
| **回答总览与说明卡** | 让长回答变成可逐级阅读、可分别追问的内容。 | 可以在提问中要求「用几张说明卡解释」。白板生成总览和 2 至 6 张说明卡，可挂出更深下级。对已有批注要求拆分时，原卡可以作为总览，同时保留查看原回答的入口。 |
| **拆分模块 / 多级拆分** | 把概括性模块继续拆成可理解或可落实的细节。 | 单选模块后使用。可生成说明卡，或生成带依赖与验收条件的任务卡。普通任务拆分一轮新增一层，多级拆分要求新增两到三层。每轮最多六张新增卡，校验后挂回选中模块。也可在问题中明确范围，生成的子节点可以继续拆。 |
| **整理白板** | 按当前项目进展更新板上的主干、已完成、待优化和参考内容。 | 打开弹窗查看范围，填写「本次整理意见」后提交。默认意见可在「整理选项」保存，单次意见可在提交前改写。模型提出分类、文字、父子或布局方案，校验后应用。正式内容参与整板整理，独立草稿仍留在原处。 |
| **整理分支** | 调整一个模块及其下级的内容顺序、组织方式和局部排布。 | 选中根卡使用，范围包括收起的下级。按钮采用默认整理意见，也可从提问中提供本轮意见。结果作用于该分支，可更新已有卡片文字和分支内归属，根卡作为位置锚点。 |
| **重新生成分支** | 纠正一整支内容的事实偏差或表达方式。 | 选中根卡，在弹窗里填写「重写意见」。逐张重写根卡与全部下级，范围包括折叠卡，卡片编号和父子关系须通过核对。可用「撤销整理」恢复。 |
| **独立提问、整合到白板** | 先讨论和验证新方向，成熟后才放进正式结构。 | 侧栏可独立提问，右键可指定起点。草稿根卡下可以继续问、拆分或整理。验收后点「整合到白板」，AI 从正式卡片里选择归属，本地将草稿根卡接入，内部下级整体随行。没有明确父卡时保留独立状态。 |
| **整理选项 → 归位孤立卡片** | 修复已有卡片缺少上级的情况。 | 有选区时查找所选孤立卡，空选区时查找整板里可归位的孤立卡。模型返回推荐父卡或留空，白板校验后保存关系。需要自己指定父卡时可直接使用连线。 |
| **撤销整理 / 撤销重排 / 撤销删除** | 让结构、内容和位置的修改可以回退。 | 从对应按钮恢复最近一次保存的快照。原始画布的手动连线可用「撤销连线」，整理后的画布使用「撤销整理」。整板模板替换使用自己的恢复入口。代码变更需通过源码差异或 Git 处理。 |

想决定该用哪个入口时，可以先确认变更范围。只改当前位置用拖动或快速重排。需要改一支的结构用「整理分支」。希望沿原有结构重新核实每张卡，用「重新生成分支」。要追加能逐级下钻的内容，用「多级拆分」。整板和分支整理当前每次最多处理 64 张卡，内容较多时可先选一个下级模块。

结构校验和结果应用见 [server.py](../server.py)、[app.js](../app.js) 和 [board_tools.py](../board_tools.py)。对应浏览器用例包括 U23、U26 至 U29、U38、U46 至 U49、U59 和 U60。

## 5. 服务连接、附件与执行过程

| 功能与入口 | 要解决的问题 | 操作结果与边界 |
| --- | --- | --- |
| **连接设置 → Codex** | 用本机 CLI 核对项目源码，在获得授权后执行受限改动。 | 使用已安装并登录的 Codex CLI。可填模型 ID，留空用该 CLI 默认值。支持分析绑定目录、问答和生成白板结构。 |
| **连接设置 → ZCode** | 复用本机 ZCode 的账号、模型和工具链。 | 使用已安装并登录的 ZCode CLI。模型可填写 ZCode 配置中的 `供应商ID/模型ID`。支持仓库分析、结构化白板操作和受限改码。CLI 的存在与本轮登录、模型可用性分别检查。 |
| **连接设置 → API 直连** | 只有模型接口时也能问答、拆分和整理。 | 填兼容 OpenAI Chat Completions 的基础地址、模型和 Key。外部地址须为 HTTPS，本机接口允许 HTTP。模型支持工具调用时，整理可用限定的白板函数，通过本地校验后应用。可用输入是白板提供的上下文和附件，项目文件和 shell 由 CLI 路线处理。Key 和地址随刷新清除。 |
| **允许本次修改代码** | 让讨论中的「改代码」有明确的执行授权。 | 先确认问题、选区、附件、服务和模型，再勾选并发送。内容变化或发送后都会清除授权。绑定项目的仓库分析为只读。当前改码能力针对白板原型允许编辑的前端文件，服务校验后才应用。 |
| **添加附件、拖入文件、Ctrl + V** | 让截图和文档成为当前讨论的一部分。 | 可从选择器添加、拖进画布或提问框，也可把截图粘贴到提问框。先进入附件列表，点「发送」后上传。每个文件最多 10 MiB，每轮最多 16 个，含本轮从相关卡片继承的附件。 |
| **继续讨论带附件的卡片** | 沿同一条分支追问时保留证据。 | 白板保存本地附件和引用，再问时按选区准备相关文件。CLI 在本机处理可用文件，实际识读取决于后端和模型，ZCode 适配器也支持传入 PDF。API 直连会将 PNG、JPEG、WebP、GIF 或 UTF-8 文本发送给配置的接口，合计最多 20 MiB，每个文本最多 120 KB。 |
| **需求卡与验收附件** | 从能力需求追到实现和验证，并阅读可复用的细节说明。 | 本机项目可用快照为指定卡片关联需求编号、需求、实现方法、验收编号和说明附件。展开验收场景查看条件，点击附件读原文件。 |
| **执行过程、查看模型返回** | 判断模型在读什么、做了什么，以及为什么没有落板。 | CLI 执行期间可查看工具步骤、文件路径和部分输出，允许时可展开短源码或改动片段。结构无效时可从执行过程或批注查看原因和脱敏返回片段。执行步骤保留在当前页面。 |
| **停止、失败后重试** | 控制耗时请求，并在输出不合规时恢复。 | 停止后白板拒收该轮迟到结果，CLI 会尝试终止本机进程。API 已发出的 HTTP 调用可能运行到返回或超时。失败时保留已保存内容，已有问题可从批注重试。 |

模型返回需要落成卡片或更新关系时，服务会检查字段、编号、卡片数量和父子关系。ZCode 可能夹带开场白、代码围栏或收尾说明。解析会尝试提取唯一完整的 JSON 对象，校验仍失败时可在同一会话内修正一次。无效结构无法提交，界面会显示具体原因。这套检查覆盖操作判断、解释、拆分、整理与重写、初始化和归位。

服务能力见 [backends.py](../backends.py)、[server.py](../server.py)、[api_backend.py](../api_backend.py)、[attachments.py](../attachments.py) 和 [agent_trace.py](../agent_trace.py)。执行过程及新分支的回归包括 U57 至 U60。

## 10. 使用路径与维护核对

### 从陌生仓库读到一个可修改的功能

1. 新建白板并绑定项目目录，用 Codex 或 ZCode 初始化工程介绍。先核对总览的边界，再展开最关心的一支。
2. 针对具体卡片提问。可以要求「按用户动作、涉及的文件、调用顺序、修改约束和验证方法往下拆两层，每个结论写可核对的源码依据」。
3. 从卡片上的源码依据打开文件，先核对当前实现和已有测试。发现说明过时，给「重新生成分支」写清重写范围和证据。

### 从新想法到代码与测试

1. 在空白处新建独立卡，写出问题和预期。和 AI 讨论后，把稳定的规则确认成项目决定，或作为约束卡连到相关模块。
2. 拆出任务与测试用例。用例写清前置、操作和可观察的断言。例如「收起含‘事件流’的分支，搜‘事件流’后应展开到目标并选中，点‘回到总览’应恢复原折叠状态」。
3. 按 TDD 工作时，在仓库里先运行能暴露问题的用例，修改后复跑，记录命令、结果和源码变更。再将确认过的草稿整合回合适的父卡，检查下级计数、折叠和刷新后的归属。

### 改功能时更新对应章节

| 改动类型 | 需要核对的行为 |
| --- | --- |
| **界面与导航** | 对照界面上的实际入口和按键。检查空白处、卡片、提问框各自接收的键鼠操作，以及缩放后命中是否正确。 |
| **卡片和父子关系** | 检查新增、重挂、折叠、刷新、撤销。观察父卡的下级计数、旧关系断开、新关系保存，以及相邻分支的位置。 |
| **模型、附件和结构化结果** | 对照实际发送的选区、上下文、授权与附件。测试成功、无效返回、停止和存储冲突。确认失败后原卡可读、错误可定位。 |
| **项目功能与验收** | 从目录到卡片核对源码依据，保存用例和执行结果。区分离线合同、浏览器模拟、实际服务三类证据，记录当前仍需人工确认的结果。 |

浏览器验收入口为 `node docs/acceptance/run_browser_acceptance.mjs`，可用 `BROWSER_CASES` 指定用例编号。离线验收入口为 `python -B docs/acceptance/run_offline_acceptance.py`。模拟测试用于核对交互和数据契约，供应商登录与模型输出需在对应服务上验证。当前已知 U28 可在原有版本复现，整理后展开部分折叠细节时，与父卡的间距可能过大。 [浏览器验收用例](acceptance/run_browser_acceptance.mjs) · [离线验收说明](acceptance/README.md)
