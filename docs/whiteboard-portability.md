# 白板导入、导出与副本

白板的「管理」菜单包含三个入口，不需要调用模型：

- **复制白板（Fork）**：从当前画布创建独立副本，可改名后继续讨论或尝试不同的结构。原白板保持原样。
- **导出白板**：下载带版本号的 `.whiteboard.json` 文件，用于备份或交给其他白板实例。
- **导入白板**：选择导出文件，核对卡片数量、填写名称，创建并打开一张新白板。首页的「独立白板」也有导入入口。

导入或复制都会分配新的白板编号。卡片编号在每张白板内部独立，因此无需更改 E/A 编号；历史问题的白板编号会改为新白板。副本后续的删除、移动和讨论不会影响原白板。这是文档副本，目前不提供版本合并或跨副本同步修改。

## 保留什么

文件保留模块内容、讨论及其引用、任务和验收描述、项目目标与约束、确认的决定、图钉、父子关系、手动连接、正文及分支折叠、布局模式和卡片位置。尚未手动编辑过的内置示例卡也会物化到文件中。

导出取当前页面的内容，而不只是读取存储，因此能包含当前模板生成的卡片。导入保留文件的排布，不自动执行快速重排。两份白板可以有相同名称，但始终有不同编号。导入窗口默认在原名称后加「副本」。

## 文件和环境边界

- 单个白板文件最多 **24 MB**，JSON 必须能通过当前版本校验。损坏文件、不支持的版本、重复卡片编号或循环父子关系会显示原因，不创建白板。
- 附件仅携带名称、大小和引用编号，不打包文件内容。在同一附件存储可继续引用；跨机器需要重新提供附件。
- 外部网页、本地图片、论文和代码仓库不随 JSON 打包。内置页面的专用图片和讲解扩展也不属于通用白板文件。
- 不导出连接配置、API Key、本机项目注册编号或项目绝对路径。导入时可自选新的本机项目目录；复制时目录输入框沿用当前目录，仍可修改。
- 副本不继承原白板的撤销历史和模板备份，也不继续原来正在执行的模型请求。导入后正常产生本副本自己的撤销记录。

导入在卡片和组织数据写入成功后才登记到白板清单。浏览器存储不足等写入失败会清理本次新建内容，原白板不会被覆盖。

## 格式与验证

格式和版本号由 `board_transfer.js` 统一处理，内容分为 `memory` 与 `organization`。文件是白板内容数据，不执行其中的 HTML、JavaScript 或模型工具指令。

```powershell
node --test test_board_transfer.js
node --test test_board_transfer_memory.js
node test_board_transfer_browser.mjs
```

浏览器测试使用独立临时浏览器与模拟本地服务，覆盖导出再导入、复制和刷新、内置示例卡、父子关系、手动连接、折叠和位置、原板隔离以及失败处理，不调用真实模型。
